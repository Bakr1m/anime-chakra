# AGENTS.md: Chakra Lens (hybrid edition)

Persistent rules for the autonomous build. Read fully before every session.

## 1. Mission

Build **Chakra Lens**: real-time AR where the camera sees a person, tracks their hands, recognizes
anime-style hand signs, and renders chakra effects attached to the hands, styled like the source
character as closely as procedural graphics allow.

It ships as **two surfaces sharing one brain**:

1. **Web app (primary, runs on phones and desktops).** TypeScript + MediaPipe + Three.js/GLSL. All
   inference on-device in the browser. Cinematic effects. Installable as a PWA.
2. **Python/OpenCV package `chakralens` (lab + desktop).** Desktop webcam CLI, dataset tooling
   (record, extract landmarks from phone-recorded videos), model training/evaluation/export, and
   benchmarks. Reuses the same gesture spec. Its OpenCV renderer is deliberately a simpler,
   documented, lower-fidelity version of the web effects.

AI-engineer portfolio project: fully working, tested, documented, containerized, shipped through
CI/CD. A recruiter should be able to open the live demo on their phone within 30 seconds.

   `docker`, `ci` where useful. Never squash, never `wip`. `git log --oneline` must read like a story.

5. **No push until the Ship phase.**

7. **Honesty**: claim only what a test, a measured number, or a screenshot proves. Never invent
   benchmarks. You cannot test on a physical phone: say so in the README ("verified with Chromium
   mobile emulation; real-device numbers: see docs/DEVICE_TESTING.md") and provide the tooling so a

   Makefile targets, `bash -c`, `sh -c` or `eval`, and never try to bypass a denied prompt. Say in one
   sentence what the command does before running it. The only exception is code that runs on GitHub's

## 5. Architecture

Web, per frame:
```
video -> HandLandmarker (+ Segmenter every 2nd frame, FaceLandmarker every 3rd, only if a jutsu needs it)
 -> OneEuro smoothing -> features -> classifier (rules from spec + MLP ensemble)
 -> state machine (hysteresis, charge, cooldown) -> active Jutsu -> Three.js layers -> bloom -> screen
```
Python, per frame: `cv2.VideoCapture -> mediapipe HandLandmarker -> same features/rules/state machine
-> OpenCV renderer (numpy additive layers, GaussianBlur bloom) -> cv2.imshow`.

`Jutsu` interface (web): `id, displayName, character, requires{hands,segmentation?,face?},
onActivate, update(dt, ctx, charge), render(renderer), onDeactivate, dispose`. Adding a jutsu = one
folder + one entry in `spec/gestures.json`.

**Cross-language parity is a hard requirement.** `spec/FEATURES.md` defines the math. Python generates
`spec/fixtures/*.json` (seeded). A Vitest test and a pytest test both load them and must produce
identical labels and features within 1e-4. A CI job named `parity` fails the build on drift.

Performance budget (web): >= 30 FPS at 1280x720 desktop and >= 24 FPS at 640x480 on mobile; effect
update+render <= 8 ms desktop. `?debug=1` shows FPS/latency and a "Copy device report" button (UA,
resolution, delegate, avg/p95 frame time) so humans can paste real phone numbers. Adaptive quality:
if FPS < 24 for 2 s, reduce particles/bloom resolution silently.

## 6. Gesture spec

MediaPipe indices: 0 wrist, 4/8/12/16/20 tips, 5/9/13/17 MCPs, 6/10/14/18 PIPs. Normalize by
hand size = dist(wrist, middleMCP). Features: finger extension ratios, curl angles, spread, palm
normal (sign-fixed by handedness), pointing vector, openness, two-hand features (wrist distance,
finger-line intersection, relative heights). Handedness-agnostic (camera is mirrored).

| Jutsu | Character | Hands | Sign |
|---|---|---|---|
| Rasengan | Naruto | 1 | Palm to camera, five fingers semi-curled, cupped "holding a ball" (openness 0.4 to 0.75, low spread) |
| Chidori | Sasuke / Kakashi | 1 | Knife hand: four fingers extended together, thumb tucked, pointing mostly horizontal |
| Katon: Gokakyu | Sasuke / Itachi | 2 | Tiger seal: hands touching, index+middle extended together pointing up, rest folded; hold 0.5 s then fires |
| Kage Bunshin | Naruto | 2 | Cross seal: index+middle extended on both hands, finger lines crossing in an X; one-shot |
| Sharingan (stretch, web only) | Sasuke / Kakashi | 1+face | Index tip within 1.2 eye-widths of an eye -> that iris turns red with tomoe |
| Kurama Cloak (stretch, web only) | Naruto | 2 | Both fists clenched and raised above shoulder -> orange aura on silhouette |

Reliability: activate after 6 consecutive matching frames, release after 8 non-matching; confidence
>= 0.75; charge ramps 0 -> 1 over ~0.6 s (ease-out); cooldowns Katon 4 s, Kage Bunshin 6 s;
two-hand jutsus outrank one-hand jutsus while both hands are visible. All constants live in
`spec/gestures.json`, never hard-coded twice.

ML: small MLP trained in Python (`chakralens train`) on normalized, rotation/scale/noise-augmented
landmarks. Baseline data = **synthetic** from parameterized finger-curl prototypes (`synth.py`), plus
any real data found in `data/`. Export to `models-export/classifier.json`; both TS and Python run the
same tiny forward pass (parity-tested). Final decision = ensemble of rules and MLP (disagreement
requires higher confidence). Report honest metrics labelled "synthetic-trained baseline" with a
confusion matrix in `docs/img/`.

**Real-data path (important for credibility):**
- Web recorder (key `R` / on-screen button): pick a label, record 3 s, download JSON (schema in spec).
- `chakralens record --camera 0 --label rasengan` (OpenCV window) does the same on desktop.
- `chakralens extract videos/ --out data/` runs HandLandmarker over phone-recorded clips (folder name = label)
  using OpenCV frame decoding and writes landmark samples. Document: "film 20 s per sign on your
  phone, drop the clips in `videos/<label>/`, run `make train`".

## 7. Visual spec: "real-looking, as the character"

Procedural only: original code and shaders, no ripped frames/sprites/audio. Additive blending over
live video, then bloom. Colors are dominant-hue targets.

**Rasengan (Naruto).** Dense sphere, radius ~0.9x hand size, floating above the palm center. Core
near-white fading to cyan-blue (#4FC3FF -> #1565C0). Surface: domain-warped fBm noise in polar
coordinates producing **fast rotating spiral streaks**, a thinner counter-rotating shell, bright
fresnel rim. 250 to 400 particles on tight orbits plus a few tangential wisps. Pulses while charging,
spring-physics wobble following hand motion. Casts blue light on nearby video pixels.

**Chidori (Sasuke).** Blue-white electricity (#BFE9FF core, #4DA3FF glow, violet edge hint).
Recursive midpoint-displacement bolts (3 to 5 levels, side branches) from palm/fingertips into a
forward cone plus a few sideways; regenerate every 2 to 3 frames (~30 Hz flicker), random width and
brightness. Hot glowing core, gravity-affected sparks, luminance flash and 2 to 4 px screen shake
scaling with charge. Synth audio: bandpass noise 2 to 6 kHz modulated ~30 Hz plus a thin chirp sweep.

**Katon: Gokakyu.** On release, a fireball emerges at the mouth (FaceLandmarker lips; fallback: above the
hands), grows 0.3 -> ~2.0x head size traveling toward the camera. Layered scrolling noise fire, ramp
black -> deep red -> orange (#FF6A00) -> yellow -> white core; billowing smoke edges; embers; warm
orange light cast on the person. Synth rumble/whoosh.

**Kage Bunshin.** Cross seal -> thick white poof (animated billboards, noise alpha) at 2 to 4 clone
spots. Clones = the user's segmentation-masked cutout, offset left/right, slightly different scale,
~85% opacity, mild desaturation, 150 to 400 ms lag. After ~5 s each dissolves in another poof.

**Sharingan (stretch).** Red radial iris (#D50000 -> #8B0000), black pupil ring, three orbiting tomoe,
thin outer ring, follows iris landmarks, clipped by the eyelid contour.

**Kurama Cloak (stretch).** Orange-gold (#FF8F00 -> #FFD54F) flame-like edge glow along the segmentation
mask, animated noise displacement, rising embers.

**OpenCV renderer (Python, reduced fidelity, documented as such).** Core four only. numpy additive layers,
`cv2.GaussianBlur` multi-scale bloom, Rasengan via polar-warped noise texture rotated per frame,
Chidori via recursive bolts drawn with `cv2.polylines` at several widths, Katon via noise-driven
flame ramp, Kage Bunshin via MediaPipe selfie segmentation compositing. Must reach >= 20 FPS at 640x480
on CPU; measure and report.

**Automatic visual QA (required).** Web `?demo=<jutsu>` drives each effect with a synthetic hand,
seeded RNG, deterministic time. Playwright asserts per screenshot: (a) dominant hue in the effect ROI
is in range, (b) luminance peak and bloom radius exceed thresholds, (c) two timestamps differ (it
animates). Run for desktop AND mobile viewports. Python renderer gets the same metric tests on
headless-rendered frames. Commit screenshots to `docs/img/` for the README. If your model accepts
image input, look at them and iterate until convincing.

## 8. Mobile requirements (web)

- `getUserMedia({video:{facingMode:'user', width:{ideal:640..1280}, frameRate:{ideal:30}}})`, `playsinline`,
  `muted`, handle iOS Safari quirks; request camera only after a tap; camera flip button (front/back).
- Portrait and landscape: layout and renderer resize on `orientationchange`; effect scale uses hand
  size, never fixed pixels. Cap devicePixelRatio at 2. Use `100dvh` and safe-area insets.
- Fullscreen button, Screen Wake Lock while running, pause on `visibilitychange`.
- Touch-first HUD: large jutsu cards with a hand-sign hint image/diagram, mute toggle, quality toggle.
- Default to 640x480 on mobile, 1280x720 on desktop; GPU delegate first, CPU fallback with a toast.
- PWA: manifest (name, icons generated programmatically, `display: fullscreen`), service worker with
  cache-first for models/wasm so it works offline after the first load.
- Reduced motion and photosensitivity guard (< 3 flashes/s, warning toggle).

## 9. Getting it on a phone (document all in README, implement all)

1. **Live demo**: GitHub Pages deploy of the web build (HTTPS, works on any phone). Vite `base` from env.
2. `make phone`: `docker compose --profile tunnel up` runs cloudflared quick tunnel, prints the
   `https://*.trycloudflare.com` URL and a terminal QR code (`chakralens qr <url>`).
3. `make phone-lan`: `docker compose --profile https up` (Caddy `tls internal`), prints
   `https://<lan-ip>:8443` + QR. README explains the one-time certificate warning honestly.
4. Dev: Vite with `@vitejs/plugin-basic-ssl` exposed on LAN (`npm run dev:phone`).
Plain `docker run -p 8080:8080` works for desktop via `localhost` (secure context).

## 10. Testing

- Web unit: features, each gesture with `makeHand()` fixtures (positive and negative), state machine,
  OneEuro, lightning determinism, classifier loader. Coverage >= 80% on `gestures` and `filters`.
- Python unit: same coverage target on `gestures`, `datasets`, `training`; synth generator ranges; train
  smoke test; export round trip; OpenCV renderer metric tests (headless).
- `parity` suite (see section 5), run in both languages.
- E2E (Playwright, fake camera flags): app loads, permission flow, canvas non-blank, `?demo=` visual
  assertions, no console errors, projects `desktop`, `iphone-14`, `pixel-7`, PWA manifest + service
  worker registers, offline reload works after first load.

## 11. CI/CD

`.github/workflows/ci.yml` on push to `main`, tags `v*`, PRs:
1. `web`: Node 22, `npm ci`, lint, typecheck, vitest+coverage.
2. `python`: Python 3.11 (+3.12 matrix), ruff, mypy, pytest+coverage.
3. `parity`: runs both fixture suites, fails on drift.
4. `e2e`: Playwright (3 projects), upload screenshots/report artifacts.
5. `docker` (needs 1 to 4; only `main` and `v*`): Buildx+QEMU, login via `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN`
   and GHCR `GITHUB_TOKEN`; matrix builds `anime-chakra` (web, nginx) and `anime-chakra-lab` (python
   headless: train/extract/evaluate/bench) for `linux/amd64,linux/arm64`; tags `latest`, short sha, semver;
   gha cache; smoke test (run container, curl `/healthz` and `/`; lab image runs `chakralens --help` and a
   tiny `evaluate`).
6. `pages` (needs 1 to 4, only `main`): build web with Pages base path, deploy with
   `actions/deploy-pages`.
Also Dependabot, status badges, Makefile targets: `dev build check test lint e2e py-test parity train
extract docker-build docker-run phone phone-lan`.

Docker: non-root, `HEALTHCHECK`, nginx gzip, `application/wasm` MIME, long cache for hashed assets,
no-cache for service worker, `Permissions-Policy: camera=(self)`, `/healthz`.
